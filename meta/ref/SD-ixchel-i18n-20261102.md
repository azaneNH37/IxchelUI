# Ixchel 模板 i18n

## Summary

模板 i18n 采用元素级消息：元素上写 `t="键"`，译文在 MC 语言 JSON 中；译文用 `%s`/`%n$s` 按位置插入不带 `mark` 的子元素，用 `<名>…</名>` 包裹文字、复制带 `mark="名"` 的子元素，每个标记可用 0..n 次。样式只由模板与 CSS 决定，译者只决定文字、标记范围与语序；依赖数据的文本由 Java 返回 `Component`。译文在加载期展开、先于绑定编译，切换语言随资源重载重建。

## Detail

### 1. 参照系

**MC**

- 翻译单元是 `assets/<ns>/lang/<locale>.json` 的扁平"键 → 字符串"，资源包按键合并覆盖；汉化生态（Crowdin、只含语言文件的汉化包）只认语言文件。
- 占位只有 `%s`、`%n$s`、`%%`；参数可以是带样式、可点击的 `Component`。缺键显示键名。无复数、无数字格式化。
- 句中样式的实际做法是把标记写进译文，译者决定标在哪、标几处，外观由代码决定：Create 的 `_…_`（颜色由 `TooltipHelper` 调色板定），Patchouli 的 `$(l)…$()`、`$(l:entry)`（书页 `i18n: true` 时从语言文件取文本）；另有大量 mod 直接写 `§` 格式码。Create 同一键的四种语言（`mc1.20.1/dev`，`assets/create/lang/`）：

```
en: "_Converts_ any _full block_ into a decorative panel. Also accepts _Bars_ and _Trapdoors_."
zh: "能将任意_完整方块转变为_装饰板，_栏杆_和_活板门_同样适配。"
ru: "_Преобразует_ любой _твёрдый блок_ в декоративную панель. Также принимает _прутья_ и _люки_."
```

高亮个数（英 4、中 3）与范围（中文"完整方块转变为"不按词切）随语言变，俄语词形在高亮内部变格。

**Web**

| 类别 | 代表 | 形态 |
|---|---|---|
| 源文本即消息，按语言出包 | Angular `i18n`、`i18n-title` | 模板写原文，属性另标 |
| 键 + 运行时函数 | i18next `t()`、vue-i18n `$t()`、`v-t` | 表达式中任意调用，键可动态 |
| 元素级消息 + 覆盖 | Fluent `data-l10n-id`/`data-l10n-name`、vue `<i18n-t>`、react `<Trans>` | 键在元素上，句子在译文中，功能子元素由模板提供、位置由译文定 |

HTML 标准只有 `lang` 与 `translate="yes|no"`，没有语言键属性。`t` 作为函数名是约定俗成的，作为属性名对应 vue 的 `v-t`。

### 2. 约束

| # | 约束 | 依据 | 排除 |
|---|---|---|---|
| C1 | 译文落在 MC 语言 JSON，汉化包只覆盖语言文件即可 | MC 生态 | 按语言分模板、FTL、ICU、源文本即消息 |
| C2 | 键是字面量，缺键与参数不符在加载期或 lint 报出 | #003 | 动态键 |
| C3 | 表达式无函数，新 `$` 名字须过四条不变式 | 语言文档 §6-2、上下文模型文档 §2 | `$t()` |
| C4 | 外观归 CSS，行为归模板 | #019、#016 | 译文自带元素、属性或样式（含 `§` 码） |
| C5 | 切换语言即资源重载，文档整体重建 | `UiHud.reload` 挂在 reload 监听上 | 运行时响应式取值 |

### 3. 形态

```html
<button t="ixchel_sample.machine.sides" on:click="sidesOpen = !sidesOpen"></button>
<mc-slot bind:menuslot="fuelSlot" t:title="ixchel_sample.machine.fuel"></mc-slot>
<div class="text" t="ixchel_sample.guide.flow">
  <span mark="hl" class="hl"></span>
  <a mark="link" on:click="open('circuits')"></a>
  <mc-item class="icon" bind:item="icons.redstone"></mc-item>
  <span bind:text="count"></span>
</div>
```

```json
"ixchel_sample.guide.flow": "Text flows across <hl>spans</hl>, <hl>colors</hl> and <link>links</link>; %2$s items like %1$s."
```

**元素与属性**

- `t="键"`：元素内容由译文给出。不能与 `bind:text` 同在；不能写在内容由宿主填充的元素（`<input>`、带载荷的原生元素、行内容元素）与组件外壳元素上。
- `t:<属性>="键"`：属性值取译文；不解析标记与参数，`%%` 仍为 `%`。
- 依赖数据的文本（枚举、状态）由 Java 返回 `Component.translatable`，经 `TextConverter` 保留样式；模板中无动态键、无 `$t()`。
- `translate="no"`（HTML 标准）：其子树不需要翻译，免于字面文本警告。

**`t` 元素的子节点**

- 带 `mark="名"` 的子元素是标记：模板中必须为空；名字在同一 `t` 元素内唯一；只能出现在 `t` 元素的直接子元素上。
- 不带 `mark` 的子元素是参数，按出现顺序编号 1、2…（只在参数间计数）。
- 子元素间只含空白的文本丢弃；非空白文本报错。
- `<for>`、`<if>`、`<slot>` 产生的元素个数不定，不能作参数或标记，须外包一个元素。
- 参数元素自身可带 `t`。

**译文语法**

```
text    := ( literal | mark | arg | "\n" )*
mark    := "<" name ">" literal* "</" name ">"     复制名为 name 的标记元素，标签内文字为其内容
arg     := "%s" | "%" n "$s"                      原样插入第 n 个参数元素（%s 按出现次序取下一个）
literal := 其余字符；"%%" 为 %
```

- `<` 只在紧跟已声明的标记名（或 `/名>`）时是标签，其余为字面字符。
- 标记不嵌套、标签不带属性；叠加样式在模板中写成一个标记（`class="b i"`）。
- `\n` 是强制换行；只对译文生效，模板源码里的换行仍按 `white-space: normal` 折叠。
- 其它 `%` 格式（如 `%d`）报错。

**数目规则**

| 情况 | 基准语言 `en_us` | 其它语言 |
|---|---|---|
| 引用的参数编号超出 | 报错 | 报一次，位置留空 |
| 有标记或参数未被引用 | 报错 | 允许，该元素不进树 |
| 同一参数或标记引用多次 | 允许，每次复制一份（先于绑定编译） | 同左 |

**展开时机**：解析后、`Compiler` 编译绑定前，按翻译端口取译文，把 `t` 元素的子节点重排为"文本、复制的标记、参数元素…"。`on:click`、`bind:*` 按最终树编译，每份复制各自绑定（Fluent 克隆丢事件监听的问题不出现）。组件体、`<for>` 行内容在模板树上展开，实例化时随 `copyTemplate` 复制。

**排版**：只含纯文本的 `t` 元素是一个文本节点，在 flex 容器中照常显示；含标记、参数或换行时是文本与元素混排，须处在行内上下文（`display: block`，#019）。

### 4. 控制权

| 角色 | 文件 | 控制 | 不能控制 |
|---|---|---|---|
| 模板作者 | `.html` | 有哪些标记、标记的元素种类、class 与行为 | 译文 |
| CSS 作者、主题 | `.css` | 每种标记的外观；按语言区分外观（`:lang()`） | 哪些字被标记 |
| 译者、汉化包 | `lang/*.json` | 文字、标记范围与次数、语序、参数位置 | 颜色、字体、属性、新标记种类、嵌套 |
| Java | 代码 | 参数 `Component` 自带的样式 | 句子结构 |

坏的或恶意的译文最多让已声明的元素多复制几份，不能加入新的行为或样式。

**`:lang()`**：mc 层把当前游戏语言（`zh_cn` → `zh-cn`）写到文档根的 `lang` 属性，CSS 以 `:lang(zh) .hl { font-style: normal }` 按语言调整外观（MC 字体的汉字斜体效果差）。

### 5. 检查

- 加载期（游戏内）与 lint：键不存在、标签未闭合或嵌套、名字未声明（后者只在看起来像标签时警告）、`%n$s` 越界、不支持的 `%` 格式、基准语言中标记或参数未被引用、标记元素有内容、`mark` 名重复或写在非 `t` 元素的子元素上。
- lint 以 `en_us.json` 为基准：资源目录与 classpath（原版 `en_us.json` 在客户端 jar 中）。
- 字面文本警告（含字母的文本节点、可翻译属性，`translate="no"` 子树与 `t` 元素除外）只在 kit 中、默认关闭，由 `lint --enable <码>` 与插件 `ixchel { lint { enable(...) } }` 打开。kit 只提供"打开默认关闭的码"，不提供关闭默认开启的码（无需要）。

### 6. 否决

| 方案 | 理由 |
|---|---|
| 表达式函数 `$t(key, args)` | 与"不提供内置函数"冲突；鼓励动态键，缺键只能运行时发现 |
| 动态键（`bind:t`） | 破坏 C2；数据相关文本由 Java 的 `Component` 承担 |
| 样式词作参数、各自取键（MC 原版式） | 词形脱离句子、范围不能跨词或切词、诱导复用、嵌套不可译、键数膨胀 |
| 编号标签 `<1>…</1>` | 译者看不出含义 |
| `_…_`/`**…**` | 只能表达一两种标记，与正文冲突 |
| `§` 格式码 | 样式交给译者，绕过 CSS 与主题，做不了链接 |
| 模板内写原文（Angular 式） | 模板与 `en_us.json` 两份原文漂移 |
| 预置 `<b>`/`<i>` 给译者 | 暂无真实场景 |
| 属性名 `i18n`/`l10n` | 更长；Angular 的 `i18n` 值是说明而非键，易误读 |

### 7. 阶段 I 结果（2026-11-02）

**引擎（core）**

- 端口 `template.Translations`：`language()`（MC 语言码）、`base()`（是否基准语言）、`get(key)`（无键为 `null`）。`TemplateParser` 解析后、编译前展开 `t`；`Message` 解析译文语法，不认识的 `<` 留作文字。
- 码在 `TemplateCode` 中，领域 `i18n`：

| 码 | 级别 | 情况 |
|---|---|---|
| `i18n/invalid-message-element` | 错误 | `t` 写在内容不归自己的元素上（组件外壳、`<input>`、`<img>`、`<select>`、原生元素）或与 `bind:text` 同在 |
| `i18n/invalid-message-child` | 错误 | `t` 元素下有非空白文本、`<for>`/`<if>`/`<slot>`、有内容的标记、重名标记 |
| `i18n/misplaced-mark` | 错误 | `mark` 不在 `t` 元素的直接子元素上 |
| `i18n/invalid-translated-attribute` | 错误 | `t:<属性>` 的属性元素不接受、不可翻译或已直接给出 |
| `i18n/missing-translation` | 错误 | 键不存在 |
| `i18n/invalid-translation` | 错误 | 基准语言译文不合法或留有未引用的标记、参数 |
| `i18n/locale-translation` | 警告 | 其它语言译文不合法，尽力显示 |
| `i18n/undeclared-mark` | 警告 | 像标签但名字未声明，按文字显示 |
| `i18n/literal-text` | 警告，默认关闭 | 模板中的字面文本、`title`、`placeholder` |

- 默认关闭由 `DiagCode.optIn()` 表达；游戏内从不报告默认关闭的码。
- `\n` 为 `TextShaper.LINE_BREAK`，行内排版据此强制换行。
- mc 两个版本的 `McResources.translations()` 以 vanilla `Language` 实现端口，文档根写 `lang`（`zh_cn` → `zh-cn`）。

**工具**

- kit `project.LanguageFiles.base(resources, classpath)`：合并资源目录与 classpath 上各命名空间的 `lang/en_us.json`（原版键来自客户端 jar），作为 lint 的基准语言；只读基准语言，其它语言的问题在游戏内以警告报告。
- `lint --enable <码>` 打开默认关闭的码；插件写法：

```kotlin
ixchel {
    lint { enable("i18n/literal-text") }
}
```

**取舍**

- 数据不翻译：任务与章节标题（数据 JSON）、建好的路径点名、配置枚举值；单位与符号（m、FE、mB、%、罗盘方位）保留字面。
- 配置项标签按 Forge 约定 `<modid>.configuration.<名>`、`.tooltip`、`.section.<名>`，由 Java 返回 `Component`。
- 服务端产生的玩家可见文本（拒绝原因）以 `Component.translatable`（键加参数）随包下发，由客户端按自己的语言解析。
- 内容本身就是样本、不可译的子树写 `translate="no"`，并以 `lang` 标明其语言（sample 的排版样张条目）。
- 单复数等两种说法写成两个 `<if>`，各取一个键；U4 起可写成 `<if>` 加 `<else>`（U4 文档 §3.3）。
